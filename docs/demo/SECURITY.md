# Безопасность демонстрации

## Модель доступа

| Кто | Как входит | Что может |
|---|---|---|
| **Ведущий** (`operator`, `admin`) | обычный вход `POST /api/auth/login` → JWT | управление сценарием, решение оператора, ссылка/QR, PDF. Каждое действие — запись в журнал аудита |
| **Другие роли** (`school`, `provider`, `district`) | обычный вход | `403` на все `/api/demo/sessions…` |
| **Зритель** | временный токен из ссылки/QR | только `GET state | stream | report.pdf` **одной** сессии |
| Аноним | — | `GET /api/demo/config`, `GET /api/demo/health` (без данных) |

**Токен зрителя.** Компактный HMAC-токен `«<срок>.<подпись>»` (≈33 символа, чтобы QR оставался простым).
Подпись — HMAC-SHA256 от `v1|<id сессии>|<срок>` отдельным ключом (производный от `JWT_SECRET`), поэтому токен:
годен только для своей сессии; истекает (`DEMO_VIEWER_TTL_MIN`, по умолчанию 240 мин); не является JWT и не принимается
ни одним другим API (проверено тестом); его срок нельзя продлить — подпись покрывает срок. Токен лежит во **фрагменте**
ссылки (`#t=…`): он не уходит на сервер в адресе, не попадает в access-логи и заголовок Referer; страница забирает его,
убирает из адресной строки и держит в `sessionStorage`. На экране зрителя токен и JWT не выводятся.
Закрытие сессии обрывает доступ немедленно (сессии нет — `404`).

**Ведущий.** `require_roles("admin", "operator")` на каждом эндпоинте управления; токен зрителя как токен пользователя
не проходит (`401`). Панель `/demo` не подсказывает учётные данные (в отличие от общей страницы входа проекта).

## Что зритель видит и чего не видит

Видит: этап, карту вымышленных школ, свежесть, показатели, затронутых школ и провайдера, ход диагностики,
результат модели с доказательствами, статус «Ожидает решения оператора», итог решения, ссылку на PDF.
Не видит и не может: любые управляющие действия; данные будущих этапов (они не попадают в JSON); заметку оператора
и его e-mail; внутренние идентификаторы БД, JWT, секреты; технические сообщения об ошибках (все отказы зрителю —
общие фразы: «Ссылка недействительна…», «Демонстрация завершена»).

## Данные

Школы, провайдеры и замеры — **вымышленные и синтетические**; названия помечены «(демо)», везде выведена плашка
«Демонстрационные синтетические данные». Данных учащихся и реальных персональных контактов нет: контакт в акте —
«Демо-контакт», телефон `+7 000 000-00-00`. Демо считает в отдельной in-memory БД; **основная БД проекта не читается
и не изменяется**, метки оператора **не** попадают в журнал аварий для обучения (в отличие от `POST /api/ml/verdict`).
`prepare` использует отдельный файл `backend/demo.sqlite`: только учётная запись ведущего и журнал аудита.
PDF и обращение помечены «ДЕМОНСТРАЦИОННЫЙ ДОКУМЕНТ … юридической силы не имеет».

## Ограничения режима DEMO_MODE

- **Выключен по умолчанию.** Без `DEMO_MODE=true` не существуют `/api/demo/*`, `/live/*`, `/demo`, статика демо;
  ничего не пишется в Redis (ключи `demo:*`). Проверено тестом (`test_demo_is_absent_in_production_mode`).
- В `DEMO_MODE` остальные API работают как обычно, поэтому для показа залу используйте **публичный режим**.
- `DEMO_MODE` меняет ровно одно поведение существующих функций: ограничивает частоту входа (`DEMO_LOGIN_RATE_LIMIT`).

## Публичный режим (`DEMO_PUBLIC=true`, `python demo.py up --public`)

Для случая, когда адрес сервера знает весь зал (или он открыт в интернет через туннель):

- подключаются **только** демо-API и вход/профиль (`/api/auth/login`, `/me`); **нет** административных, агентских,
  рабочих, ML, экспортных и AI-API, журнала аудита и политик, `/docs`, `/openapi.json` (ответы `404`);
- корень `/` отдаёт только `{"status":"ok"}`; фоновые задачи (приём агентов, внешние источники, очистка) не запускаются;
- **сервер откажется стартовать**, если `JWT_SECRET` равен значению из репозитория или у активной учётной записи
  пароль из списка по умолчанию (`admin123`, `operator123`, …) — `engine.check_public_mode`;
- `demo.py prepare` создаёт отдельную БД без учётных записей проекта и генерирует `JWT_SECRET` и пароль ведущего.

## Ограничение частоты

| Что | Ключ | Лимит по умолчанию |
|---|---|---|
| Зритель (запросы) | сессия + id вкладки | 120/мин (`DEMO_RATE_LIMIT_VIEWER`) |
| Все зрители сессии | сессия | 6000/мин (`DEMO_RATE_LIMIT_SESSION`) |
| Действия ведущего | пользователь | 120/мин (`DEMO_RATE_LIMIT_OPERATOR`); чтение состояния панелью — ×4 |
| Вход | IP | 20/мин (`DEMO_LOGIN_RATE_LIMIT`, только при `DEMO_MODE`) |
| Потоки SSE | процесс | 500 (`DEMO_MAX_VIEWERS`) → `503` |

Счётчики — общий Redis (`cache.rate_limit_ok`) или память процесса. Зрители за одним NAT не мешают друг другу:
лимит считается по id вкладки, а не по IP.

## Журналирование

`write_audit` (хэш-цепочка, существующий журнал): `demo.create`, `demo.link`, `demo.control` (действие и этап),
`demo.settings`, `demo.verdict` (решение, причина, заметка), `demo.report`, `demo.close` — с e-mail, ролью, IP.
Зрители в журнал не пишутся (нет идентичности и лишних персональных данных). Целостность цепочки проверяется
`GET /api/auth/audit` (не в публичном режиме) и тестом.

## Известные ограничения (честно)

1. **Токен один на всех зрителей** (в общем QR). Если его сфотографируют, им можно смотреть демонстрацию до конца срока
   или закрытия сессии — при этом управлять нельзя. Митигации: короткий срок, «Закрыть сессию», «Обновить ссылку и QR».
2. **Нет TLS «из коробки»**: в локальной сети ссылка `http://`. Для интернета — HTTPS на обратном прокси/туннеле
   (`--public-url https://…`); тогда включается HSTS (`DEBUG=false`).
3. **Учёт зрителей** идёт по id вкладки, который выдаёт сам клиент: это счётчик для ведущего, а не защита.
4. **Redis без пароля** (`redis://localhost`) подходит для стенда; в общей сети задайте пароль в `REDIS_URL` и не публикуйте порт.
5. **Один процесс без Redis** — состояние в памяти: перезапуск сервера закрывает сессию. С Redis она переживает перезапуск.
6. **Пороги SLA** для акта берутся из БД (`thresholds`); в демо-БД это значения по умолчанию из `config.py`.
7. **Ключ подписи токена зрителя** производен от `JWT_SECRET`: смена секрета делает все выданные ссылки недействительными.
8. Модели не подтверждены на реальных авариях школ — это сказано на экране, в акте и в тексте выступления;
   решение всегда за оператором.

## Чек-лист безопасного публичного показа

- [ ] `python demo.py up --public` (а не `--main-db`); в логе нет ошибок «сервер небезопасен».
- [ ] Пароль ведущего — из `backend/.env` (сгенерирован), не из документации; терминал на проектор не выводится.
- [ ] Наружу открыт только один порт; Redis (если есть) наружу не открыт.
- [ ] `curl http://хост:порт/docs` и `/api/web/overview` → `404`.
- [ ] После показа: «Закрыть сессию», смена пароля/удаление `backend/.env` и `backend/demo.sqlite`.
