# Архитектура демонстрации

## Схема синхронизации

```
                       ┌───────────────────────── один процесс FastAPI (или несколько) ─────────────────────────┐
 Ведущий               │                                                                                        │
 /demo (React) ──REST──▶ routers/demo.py ──▶ engine.control()/decide()/make_report()                            │
 Bearer: JWT           │   роль admin|operator      │  под блокировкой сессии:  load → изменить → save (версия+1) │
 operator/admin        │   лимит + журнал аудита    ▼                                                            │
                       │                      ┌──────────────┐   нет Redis / упал                                │
                       │                      │    Store     │──────────────▶ зеркало в памяти процесса          │
                       │                      │ Redis (общий)│                                                    │
                       │                      └──────┬───────┘                                                    │
                       │        версия (1 GET на процесс, раз в 0,5 с)                                            │
                       │                             ▼                                                            │
                       │   фоновый цикл run_loop:  таймеры сценария (tick) ─ версия изменилась? ─▶ view_json()   │
                       │                                                   (представление строится 1 раз/версию)│
                       │                             ▼                                                            │
                       │                   Hub: рассылка локальным подписчикам (очередь на 1 элемент)            │
                       └─────────────────────────────┬──────────────────────────────────────────────────────────┘
                                                     │  SSE  (event: state, полный JSON состояния)
 Зрители  /live/{id}#t=…  ◀───────────────────────────┘  либо опрос GET /state каждые 1,5 с, если поток недоступен
 (React, только чтение)
 Bearer: токен зрителя (привязан к одной сессии)
```

Ключевые свойства:

| Свойство | Как достигается |
|---|---|
| Сценарий и ML считаются **один раз** | `scenario.compute(seed)` при создании сессии (кэш по seed); результат лежит в документе сессии. Зрители получают готовое представление. Счётчик `scenario.ML_RUNS` не растёт от зрителей (тесты и `demo_load.py` это проверяют) |
| Представление строится **один раз на версию** | `engine.view_json()`: кэш по номеру версии; рассылка — одна сериализованная строка всем подписчикам процесса |
| Задержка ≤ 2 с | в том же процессе — сразу (после действия ведущего `hub.refresh`), в соседнем — до 0,5 с (цикл), опрос — ≤ 1,5 с + запрос. Измерено: SSE 17–96 мс (50–300 зрителей), 2 процесса + Redis ≤ 420 мс, опрос ≤ 1,51 с |
| Полное состояние после перезагрузки/позднего входа | каждый кадр SSE и каждый ответ `/state` — **полное** состояние, а не дельта |
| Автопереподключение | клиент: пауза 0,5→4 с; после двух неудач — опрос; раз в 30 с проба потока; «пробуждение» вкладки/сети — немедленный опрос |
| Безопасный однопроцессный fallback | без Redis `Store` работает в памяти процесса; при обрыве Redis — зеркало процесса; возврат Redis подхватывается через ≤ 5 с и он «догоняет» по версии |
| Несколько процессов | состояние и версия — в Redis; блокировка сессии `SET NX PX` (redis-py `lock`); таймеры тикают в каждом процессе, но переход выполняется под блокировкой с перепроверкой; число зрителей — общий ZSET по id зрителя |

## Модель состояния

Документ сессии (JSON, ключ `demo:doc:{id}`, версия — `demo:v:{id}`):

```
id, title, created_at, created_by, run           # run растёт при каждом «Сброс»
stage, stage_started, armed_at, substep, paused_at
settings {mode: manual|auto, intervals{этап: сек, 0 = ждать ведущего}, diag_step_sec}
decision  {kind: confirm|change, cause, at, by, note}   # note и by зрителям не передаются
report    {at, claim_text}                              # PDF — отдельным ключом demo:pdf:{id}
scn       # результат compute(): метрики школ, ход диагностики, вывод ML, материалы для PDF
version
```

### Этапы (`scenario.STAGES`)

| Этап | Что видят зрители | Переход |
|---|---|---|
| `waiting` | «Ожидание начала», серая карта | ▶ Запуск |
| `normal` | школы в норме, свежесть данных | далее |
| `incident_started` | 4 школы одного провайдера критичны; ping/jitter/потери; инцидент; график | далее |
| `diagnostics` | 4 шага по очереди (таймер сервера, `diag_step_sec`) с результатом и выводом каждого | далее |
| `ml_result` | предполагаемый источник, уверенность, достаточность данных, факторы, сезонная норма, прогноз | далее |
| `operator_review` | «Ожидает решения оператора» | **только решение оператора** |
| `operator_confirmed` | итог решения (подтверждено/изменено) | «Сформировать акт» / далее |
| `report_ready` | обращение и ссылка на PDF-акт | далее → `reset` |
| `reset` | исходное состояние, «Запуск №N» | ▶ Запуск → `normal` |

Правила переходов (`engine.control`, `_gate`, `_enter`): вперёд через `operator_review` без решения — `409`
(и для ручного `next/goto`, и для таймера); переход назад сбрасывает решение и отчёт, если они относились
к более поздним этапам; повторный `start` безопасен (ничего не меняет); `reset` увеличивает `run` и очищает всё.

`build_view(doc)` — чистая функция: то, что показывается на текущем этапе, **и только это**. Данные будущих
этапов (вывод ML, решение, отчёт) в JSON не попадают вообще — зритель не может «подсмотреть вперёд» через
инструменты разработчика (тест `test_full_flow_and_no_lookahead`).

## ML: что настоящее, а что синтетическое

`services/demo/scenario.py`:

1. Синтетическая область: 12 вымышленных школ, 3 вымышленных провайдера, 3 района; для каждого устройства —
   14 суток замеров (каждые 30 мин) и последние 2 часа (каждые 5 мин). Генератор детерминирован (`random.Random(f"{seed}:{device}")`),
   шум ограничен: ложных аномалий не бывает — любая аномалия следует из заданной аварии.
2. Данные кладутся в **отдельную in-memory БД** (`sqlite://`, `StaticPool`). Боевая БД не читается и не пишется.
3. **Настоящие модели проекта** (`services/ml`) применяются к этим данным без подмены:
   - сезонная норма: `baseline.profiles_from_rows` → профили «час × тип дня»; `baseline.snapshot(…, store=…)` → аномалии;
   - классификатор источника: `attribution.diagnose` (веса `backend/models/attribution.json`), слой достаточности данных и потолок уверенности;
   - прогноз: `forecast.predict` (веса `forecast.json`) — риск нарушения SLA на 6 часов.
4. Ответ **не написан заранее**: если веса моделей изменятся, изменится и вывод. `python demo.py check` и тесты проверяют,
   что вердикт — `provider_node` и `source == "model"`; при расхождении подготовка останавливается с сообщением.
5. Ход диагностики (4 шага) строится из доказательной базы этой же модели (`evidence`), а не из шаблона.
6. Обращение и PDF используют существующие `_fallback_claim` и `reports.sla_report` с красной плашкой
   «ДЕМОНСТРАЦИОННЫЙ ДОКУМЕНТ … юридической силы не имеет» (новый необязательный параметр `banner`).

Изменения в существующем коде минимальны и обратно совместимы: `baseline.profiles_from_rows` (вынесенная чистая часть
`build`), необязательный `store` в `baseline.snapshot`, необязательный `banner` в `reports.sla_report`,
ограничение частоты входа только при `DEMO_MODE`.

**Что синтетическое и так помечено:** школы, провайдеры, замеры, модельное время сценария («10.03.2026 10:52»).
Обучающие данные моделей — симулятор отказов проекта; на реальных авариях школ они не проверялись —
этот текст постоянно виден в баннере, карточке модели и подвале страницы.

## API

Ведущий (роль `admin`/`operator`):

| Метод и путь | Назначение |
|---|---|
| `POST /api/demo/sessions` | создать сессию (`title`, `mode`, `intervals`, `diag_step_sec`, `public_url`) → ссылка, QR (SVG), состояние |
| `GET /api/demo/sessions`, `GET …/{id}` | список; состояние сессии (предпросмотр + `control`: зрители, режим, хранилище) |
| `POST …/{id}/control` | `start`, `pause`, `resume`, `next`, `goto` (+`stage`), `reset` |
| `PUT …/{id}/settings` | режим и интервалы |
| `POST …/{id}/verdict` | `confirm` / `change` (+`cause`, `note`) |
| `POST …/{id}/report`, `GET …/{id}/report.pdf` | сформировать / скачать акт |
| `POST …/{id}/link`, `DELETE …/{id}` | новая ссылка и QR; закрыть сессию |

Зритель (токен одной сессии): `GET /api/demo/live/{id}/state`, `/stream` (SSE), `/report.pdf`.
Публично: `GET /api/demo/config`, `GET /api/demo/health`.
